# 结束对话后重新唤醒异常修复（2026-11-16）

## 现象

唤醒后连续问答正常；说“结束/你可以走了”后机器人回复“好的”并结束。再次用
“小医小医”唤醒后，回答内容奇怪（答非所问、把闲聊续写成医学句子），有时不回答。

## 日志定位的 4 个根因

1. **ASR 给问题拼接了旧提示后缀**
   `ros_node_keyword_asr.cpp` 的 `send_question()` 会在问题上追加
   `"。提示:请用简短口语回答"`（原本给旧 question_router 用）。新网关不解析它，
   会把它当问题正文送进 prompt；本地 2B 纠错模型甚至把它当指令执行/续写。
   实测：`再讲个笑话，N。。提示:请用简短口语回答` 被改写成
   `再讲个笑话，N打了个喷嚏，结果把透析管给喷掉了`。

2. **结束后网关历史没清空**
   `/dialog_session_finished` 没有被网关订阅；`_history` 保留“好了，你可以走了 →
   好的”等结束语轮次。下次唤醒带着“刚结束”的上下文，模型容易答偏。

3. **护士告警在纠错之前拿到原始识别文本**
   ASR 先并行调用 `check_need_call_nurse`，再发网关。`内漏`（内瘘的同音误识别）
   未归类前被判为“内出血急症” → `need_call=true` → 立即 `/tts_cancel` 并结束会话。
   表现就是“刚问完就不回答/直接结束”。

4. **TTS cancel 状态残留**
   `/tts_cancel` 只清播放队列，不清合成队列、不提升会话代次；`cancelEvent`
   一直置位到下一次 `[START]`，导致呼叫护士的 oneshot 播报被直接静音。

## 修复

| 文件 | 修复 |
| --- | --- |
| `ros_node_keyword_asr.cpp` | ① `send_question` 不再拼接提示后缀；② 识别文本入口做同音字归一（内漏/内露→内瘘、血林→血磷等），护士与网关都拿到干净文本 |
| `ros2_node_llm_medical.py` | ① 入口用正则剥离任何遗留的 `。提示:...`；② 纠错增加防呆：闲聊/指令跳过、长度差 ≤25%、编辑相似度 ≥0.65 才采纳，否则用原文；③ 订阅 `dialog_session_finished` 清空历史并重置轮次；④ 会话 epoch 防止旧回答晚到的 `[DONE]`/历史写回污染新一轮 |
| `ros2_node_nurse_alert.py` | 请求文本先做同音字归一；system prompt 补充“内漏/内露=内瘘，不按内出血处理” |
| `ros2_node_tts_cosyvoice.py` | `/tts_cancel` 提升会话代次并排空合成队列；oneshot 播报前清除 cancel 标志，呼叫护士播报不再静音 |

## 验证（麦克风静音，避免 TTS 回声干扰）

1. 正常问答：`今天天气怎么样？` → 正常天气答复，TTS 播完。
2. 结束：`好了，你可以走了。` → 护士 `need_end=true`；网关日志
   `收到会话结束... 清空历史 1 组`，历史为 0。
3. 重唤醒（`/call_signal`）后问：`再讲个笑话。提示:请用简短口语回答`
   → 日志显示 `剥离 ASR 提示后缀`，意图=chitchat，纠错被跳过；
   回答 `为什么透析机从不生气？因为它心里——滤得很清！`。
4. `内漏怎么处理？` → 网关归一为 `内瘘` 并给出内瘘保护建议；
   护士返回 `need_call=false / need_end=false`（修复前会误报急症）。
5. `/tts_cancel` 后调用 `/tts_one_shot` → 正常合成 1.01s、播放 2.49s（修复前静音）。

> 测试中文本注入不经过 ASR，ASR 的 15s 会话计时器仍会触发一次
> `dialog_session_finished(timeout)` 把历史清空；这是测试方式导致，不是回归。
> 真实语音路径中识别到问题时会取消计时器，播放结束后再重置。

## 备注

- 本次不改变问答模型与知识库；默认启动方式不变，无需新增环境变量。
- 长回答场景仍建议把 `ASR_SESSION_TIMEOUT` 调到 30–60s（默认 15s）。
- C++ 节点已重新 `colcon build --packages-select llm_node_cpp`。
